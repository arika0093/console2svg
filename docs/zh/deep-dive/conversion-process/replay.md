description: 将操作以按键含义和时间保存，并作为 VT 字节序列而非 OS 依赖的原始输入重新发送的机制。
---

重放保存的不是终端输出本身，而是可再次执行的输入操作。这样可以在 PTY 中重新运行同一命令，并连同会响应输入的 TUI 一起重新记录画面变化。如果原样保存键盘的 OS 固有事件，就无法在 Windows 和 Unix 之间播放，因此文件以按键名、修饰键和时间这些通用含义来表示。

## 小巧且手写也可读的时间表示

第一个事件具有从录制开始起的绝对秒数 `time`，之后的事件保存为相对于前一个事件的差分 `tick`。差分化是为了在连续输入时避免反复写入相同的大绝对值，同时也让 JSON 更容易读写。读取时优先使用 `time`，只有 `tick` 的事件会累积并规范化为绝对时间。还包含 `version`、应用版本、创建时间和总时间，因此可以表示仅靠事件序列无法表达的记录边界。

总时间是一个边界，用于避免输入结束后子进程仍停留在提示符等待时，播放变成无限期录制。PTY 路径会设置总时间 +1 秒的期限，回退路径也设置相同期限；超时时不会含糊地当作部分成功处理，而是向调用方返回超时。

## 将按键转换为 VT

`InputReplayFile.EventToBytes` 会把 Enter、Tab、方向键、Home/End、Insert/Delete、PageUp/Down、F1 到 F12 转换为标准 VT 序列。Shift、Alt、Ctrl、Meta 会按需反映为修饰参数或 ESC 前缀。Ctrl+A 到 Ctrl+Z 转换为控制字节，普通字符和未知按键名落到 UTF-8。`type: "raw"` 会将 `key` 原样作为 UTF-8 发送，因此也能表达普通模型容纳不了的输入。

播放流会预先把事件转换为字节序列，并在被读取时等待到预定时刻。如果处理比计划滞后，则不会额外等待，而是在不打乱顺序的情况下追赶。即使一个事件比流的读取缓冲更大，也会保持偏移并分割发送，因此不会丢失输入中途内容。通过将此流连接到与普通输入转发相同的 PTY writer，手动输入和重放会共用输出获取路径。
