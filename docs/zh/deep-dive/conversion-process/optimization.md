---
title: SVG 输出优化
description: 在保持单元格网格忠实度的同时，减少 DOM 数量、字符串大小和生成时分配的方法。
---

终端本质上是按单元格组成的画面，但 SVG 不必按每个单元格一个 DOM 来输出。如果把 80×24 的画面逐字输出为 `<text>`，即使短输出也会达到数千个元素，不仅文件大小增加，查看端的 DOM 构建和布局也会变重。优化不是为了近似显示，而是在保持每个单元格含义的同时，让表达单位变粗。

## 为什么分别合并文字和背景

背景会把横向连续且有效背景色相同的范围输出为一个 `<rect>`。反色显示会在交换前景和背景后的颜色上判断，与主题默认背景相同的单元格交给父级基础背景处理。相邻矩形会叠加同色的细非缩放描边。这是为了消除缩小显示时产生的亚像素接缝，而不是让单元格边界本身看起来更粗。

文字也会把颜色、粗体、斜体、下划线、删除线、上划线、下划线颜色、闪烁都相同的连续单元格合并为一个 `<text>`。由于 `textLength` 固定为单元格宽度总和，字符串会对齐终端列边界，而不是依赖字体实测宽度。中间空格只在连接到后续相同样式字符时保留，行尾空格不输出。这是在不改变画面位置的前提下删除不可见数据的关键。

全角字符占两列，后续的延续单元格不能作为独立字符输出。另外，块元素和框线会作为图形而不是字体处理。因此，它们会成为字符串合并的边界。通过避免简单地“连接所有相邻字符”，可以防止列偏移和框线破损。

## 静态图片和视频共用的优化

样式不会每次内联，`SvgStyleRegistry` 会为唯一组合分配短 CSS 类。图形在动画的行定义中也使用 `SvgElementRegistry`，以便定义并复用相同矩形和路径。这既能缩小压缩前的 SVG 本身，也能避免在生成时反复组装相同字符串。

视频中还会通过行的视觉签名对定义进行去重。这利用的是终端即使在长时间记录中通常也只有少数几行变化的性质。

提速并不只是让 CPU 更快，而是优先创建原本就不需要生成和绘制的结构。
